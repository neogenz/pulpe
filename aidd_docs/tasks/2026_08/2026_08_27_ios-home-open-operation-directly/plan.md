# Plan: Open an operation from the accueil in one push

## Overview

| Field      | Value                                                                                                                                                                                                                                                                                                                                                             |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Goal**   | Replace the two-step push (budget, then edit page via `appState.pendingTransactionEdit`) by a direct destination on the accueil stack, hosting `EditTransactionPage` with its own coordinator; make the accueil adopt the shared detail snapshot so landing on it during the 3 s undo window neither resurrects a deleted row nor leaves it stale after commit. |
| **Source** | Maxime, chat 2026-08-27: « double navigation, d'abord le détail du budget, ensuite le détail de la transaction. On pourrait pas directement avoir le détail de la transaction dans ce contexte précis là ? » — branch `fix/ios-home-activity-swipe`, PR #686.                                                                                                     |

## Decisions

| Decision                                                                                                                                                                        | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The accueil reads `BudgetDetailCache` when the entry is fresh (`CurrentMonthStore.loadDetails` and the `onMutation` seam), instead of refetching after every detail mutation.  | Every mutation path already ends in `dataStore.syncCache()` (rule 11), so the cache is the latest truth. Refetching resurrects a soft-deleted row while its undo toast is up (server keeps it until commit) and leaves the accueil stale after the commit, because nothing reloads a visible accueil. Today this window exists on the way back through the budget page; landing on the accueil directly makes it systematic. Same 30 s cross-device lag as the budget page. |
| `EditTransactionPage` is hosted by a small view that owns its own `BudgetDetailsCoordinator` + `BudgetDetailsProjector`, exactly like `BudgetDetailsView`, not a shared one.     | The page is written against the feature's stores + projector (rule 9: mutations through `dispatch`, undo toast, `AutoPopView`). Reusing them unchanged keeps the page identical on both paths; the host only supplies environment, the sheet slot and the loading gate.                                                                                                                                                                                              |
| Sheet content moves out of `BudgetDetailsView+Routing` into one `BudgetDetailSheetContent` view used by the budget page and the host.                                            | The edit page presents `.spreadExisting` and `.spreadOccurrences` through `router.present`; a host with only those two cases and a silent default would render nothing the day the page presents a third. One switch, two callers.                                                                                                                                                                                                                                  |
| Ships inside #686 on `fix/ios-home-activity-swipe`, not as its own PR (Maxime, 2026-08-27).                                                                                                                          | One PR for the whole accueil-row change, reviewed and tested together; the plan had proposed a separate one for the ~180 net LOC on top of ~300. Rejected alternative: pushing `.details` and `.editTx` in one path update (one animation, budget kept under the page): Back would then unwind through a budget page the user never opened, the double navigation moved to the way out.                                                                                                                                  |
