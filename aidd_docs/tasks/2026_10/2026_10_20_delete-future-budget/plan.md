# Plan: Delete a future month's budget (PUL-361)

## Overview

| Field      | Value                                                                                                                                                                                                                                                                                                                  |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Goal**   | `DELETE /v1/budgets/:id` refuses the current and past months, and refuses linked months unless `confirmLinks=true`. A new read-only `GET /v1/budgets/:id/deletion-impact` lists what goes away. Every client gets "Supprimer ce mois" on future months only. The MCP connector gets a destructive `delete_month` tool. |
| **Source** | Linear PUL-361, plus the brainstorm "Agent tools for tags and templates, and deleting a future budget" (2026-10-20). The product decisions are settled and come from the workflow brief.                                                                                                                                 |

- The `settings.connections.tools.delete_month` web label belongs to phase 3, which already owns the four web catalogs.
- The iOS activity label belongs to phase 4.

## Decisions

| Decision                                                                                                                                                                                                                                                                                 | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The server owns the "future month only" rule. `RemoveBudgetUseCase` computes the live period with `getBudgetPeriodForDate(parseIsoDateLocal(formatBusinessCalendarDate()), user.payDayOfMonth)` and refuses any period at or before it, with `ERR_BUDGET_NOT_DELETABLE` (409). Clients only hide the action. | There are four clients and an agent. Only one place can enforce the rule. The business-calendar date (Europe/Zurich) is the one `get_current_month` already uses, so the agent and the rule agree on "today".                                                                                                                                                                                                                                                                                                        |
| Linked deletion is a two-step handshake. `GET /deletion-impact` is read-only. `DELETE` without `confirmLinks=true` on a linked month answers 409 `ERR_BUDGET_DELETION_LINKS_UNCONFIRMED` (with the links in `details`) and deletes nothing.                                                | A client that skipped the impact read can never silently break a spread, a savings goal or a withdrawal pair. The links stay data on the server, not a client-side guess.                                                                                                                                                                                                                                                                                                                                             |
| The deletion itself is no new logic. The existing FK cascades remove the month's forecasts, movements and tag links. The other months keep their share of a spread or a withdrawal pair. Nothing recomputes the rollover.                                                                 | The rollover is computed at read time from each month's `ending_balance` delta, so removing a month only needs the existing per-user cache invalidation. A cascade rewrite would be speculative and irreversible.                                                                                                                                                                                                                                                                                                      |
| `BudgetWritePort` gains `deletionImpact` and `removeMonth` (by month and year). Its single adapter is renamed from `CreateBudgetInProcessUseCase` to `WriteBudgetsInProcessUseCase`. The port is still bound with `useExisting`.                                                             | ADR-0002: MCP reaches the budget module only through an exported port. One port needs one adapter, and the old name would lie once the adapter also deletes.                                                                                                                                                                                                                                                                                                                                                         |
| The `DELETE /v1/budgets/:id` status codes change (404 for an unknown id, 409 for a refusal). This ships as one synchronized release (Option C).                                                                                                                                             | No deployed client calls `DELETE /budgets/:id` today: the iOS `deleteBudget(id:)` has zero callers, and the integration specs delete through the admin client. Nobody depends on the old "always 200" behavior.                                                                                                                                                                                                                                                                                                         |
| Clients show the two new error codes as the generic error. Nothing is added to the client error-code localizers.                                                                                                                                                                         | The action is only offered on future months, after a fresh impact read, so these codes show up only on races: the month became current, or a link appeared. A generic error plus a reload is enough there.                                                                                                                                                                                                                                                                                                            |
